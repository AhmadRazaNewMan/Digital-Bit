# B-tree vs LSM: OLTP vs Heavy Writes Intuition
## What
B-tree and LSM (Log-Structured Merge) are two popular indexing techniques used in databases. B-tree is a self-balancing search tree data structure that keeps data sorted and allows search, insert, and delete operations in logarithmic time. LSM, on the other hand, uses a combination of in-memory and on-disk data structures to optimize write performance.

## Why
The choice between B-tree and LSM depends on the workload of the database. For OLTP (Online Transaction Processing) workloads, which involve a high volume of random reads and writes, B-tree is often preferred due to its ability to maintain a balanced tree and provide consistent performance. However, for workloads with heavy writes, LSM can provide better performance by reducing the number of disk writes and minimizing the impact of disk seeks.

## How
In a B-tree, each node represents a range of key values and contains a list of child nodes. When a new key is inserted, the B-tree is rebalanced to maintain a consistent height. In an LSM tree, data is written to a log file and then merged into the main database in batches. This approach reduces the number of disk writes and allows for more efficient handling of heavy write workloads.

## One exercise or command
To understand the performance difference between B-tree and LSM, try running a benchmarking tool such as `sysbench` with a workload that simulates heavy writes, and compare the performance of a B-tree based database (e.g. MySQL) with an LSM based database (e.g. Cassandra).
