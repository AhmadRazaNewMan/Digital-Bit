# Normalization vs Denormalization Tradeoffs
## What
Normalization and denormalization are two database design techniques used to optimize data storage and retrieval. Normalization involves organizing data into tables to minimize data redundancy and improve data integrity, while denormalization involves intentionally duplicating data to improve query performance.

## Why
The tradeoff between normalization and denormalization is a common dilemma in database design. Normalization helps to eliminate data inconsistencies and reduce storage requirements, but can lead to slower query performance due to the need for joins. Denormalization, on the other hand, can improve query performance but increases storage requirements and can lead to data inconsistencies.

## How
To decide between normalization and denormalization, consider the following factors:
* Data consistency and integrity requirements
* Query performance requirements
* Storage constraints
* Data update frequency
A balanced approach that combines elements of both normalization and denormalization is often the most effective solution.

## One exercise or command
To illustrate the tradeoff, consider a simple example: a customer database with customer information and order history. A normalized design would store customer information in one table and order history in another, while a denormalized design would store all customer information and order history in a single table. The command to create a normalized customer table might look like: `CREATE TABLE customers (customer_id PRIMARY KEY, name, address)`.
