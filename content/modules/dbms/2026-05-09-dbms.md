# B-tree vs LSM: OLTP vs Heavy Writes
## What
B-tree and LSM (Log-Structured Merge) are two popular indexing techniques used in databases. B-tree is a self-balancing search tree data structure that keeps data sorted and allows search, insert, and delete operations in logarithmic time. LSM, on the other hand, is designed for high-write workloads and uses a combination of in-memory and on-disk components to achieve high throughput.

## Why
The choice between B-tree and LSM depends on the workload of the database. For Online Transaction Processing (OLTP) systems, which involve a high volume of small, random reads and writes, B-tree is often preferred due to its ability to handle random access efficiently. However, for systems with heavy write workloads, such as data ingestion or logging, LSM is more suitable as it can handle high write throughput without significant performance degradation.

## How
B-tree works by maintaining a balanced tree structure, where each node represents a range of key values. When a new key is inserted, the tree is rebalanced to ensure that the height of the tree remains relatively constant. In contrast, LSM uses a combination of an in-memory memtable and on-disk SSTables (Sorted String Tables) to store data. When the memtable is full, it is flushed to disk and merged with existing SSTables to maintain a sorted order.

## One exercise or command
To illustrate the difference between B-tree and LSM, consider the following example: suppose we have a database that stores sensor readings, with a high volume of inserts and occasional range queries. To evaluate the performance of B-tree and LSM for this workload, we can use the following command:
* `sysbench oltp_read_write --db-driver=mysql --table-size=1000000 --tables=10 --mysql-user=root --mysql-password=password --time=300 --report-interval=1`
