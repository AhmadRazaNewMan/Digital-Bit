# B-tree vs LSM: OLTP vs Heavy Writes
## What
B-tree and LSM (Log-Structured Merge) are two popular indexing techniques used in database management systems (DBMS). B-tree is a self-balancing search tree data structure that keeps data sorted and allows search, sequential access, insert, and delete operations in logarithmic time. On the other hand, LSM is a disk-based data structure designed for high write throughput and is optimized for disk storage.

## Why
The choice between B-tree and LSM depends on the workload of the database. For Online Transaction Processing (OLTP) workloads, which involve a high volume of small, random reads and writes, B-tree is often the better choice. This is because B-tree allows for efficient random access and update operations. However, for workloads with heavy writes, such as logging or data ingestion, LSM is more suitable. LSM is designed to handle high write throughput and can provide better performance in these scenarios.

## How
B-tree works by maintaining a balanced tree structure, where each node represents a range of keys. When a new key is inserted, the tree is rebalanced to ensure that the height of the tree remains relatively constant. This allows for efficient search, insert, and delete operations. LSM, on the other hand, works by writing data to a log file and then merging the log file into a sorted structure called an SSTable (Sorted String Table). This allows for high write throughput and efficient storage of large amounts of data.

## One exercise or command
To illustrate the difference between B-tree and LSM, consider the following command: `CREATE TABLE test (id INT PRIMARY KEY, value VARCHAR(255)) ENGINE=InnoDB;` This command creates a table with a primary key index using the InnoDB storage engine, which uses B-tree indexing. To test the performance of B-tree vs LSM, you could insert a large amount of data into the table and measure the performance of insert, update, and select operations.

## Further reading
* Characteristics of B-tree and LSM indexing techniques:
  + B-tree: self-balancing, efficient random access, suitable for OLTP workloads
  + LSM: high write throughput, optimized for disk storage, suitable for heavy write workloads
* Use cases for B-tree and LSM:
  + B-tree: relational databases, OLTP workloads, real-time analytics
  + LSM: NoSQL databases, logging, data ingestion, big data analytics
* Performance comparison of B-tree and LSM:
  + B-tree: faster random access, slower write throughput
  + LSM: faster write throughput, slower random access
