# Normalization vs Denormalization Tradeoffs
## What
Normalization and denormalization are two database design approaches that serve different purposes. Normalization is the process of organizing data in a database to minimize data redundancy and dependency, while denormalization is the process of intentionally allowing data redundancy to improve performance.

## Why
The tradeoff between normalization and denormalization depends on the specific use case of the database. Normalization is beneficial for maintaining data consistency and reducing storage costs, but it can lead to slower query performance due to the need for joins. Denormalization, on the other hand, can improve query performance but may result in data inconsistencies and increased storage costs.

## How
To decide between normalization and denormalization, consider the following factors:
* Data complexity: Normalization is more suitable for complex data with many relationships, while denormalization is more suitable for simple data with few relationships.
* Query patterns: Denormalization is more suitable for databases with frequent read operations, while normalization is more suitable for databases with frequent write operations.
* Performance requirements: Denormalization can improve query performance, but normalization can reduce storage costs.

## One exercise or command
To illustrate the tradeoff, consider a simple example: a database with customer information and order history. A normalized design would store customer information in one table and order history in another table, with a foreign key linking the two. A denormalized design would store customer information and order history in a single table. Try creating both designs and compare their performance for different query patterns.

## Further reading
* Benefits of normalization:
  + Improved data consistency
  + Reduced storage costs
  + Improved data scalability
* Benefits of denormalization:
  + Improved query performance
  + Simplified query complexity
  + Improved data availability
* When to use normalization:
  + Complex data with many relationships
  + Frequent write operations
  + High data consistency requirements
* When to use denormalization:
  + Simple data with few relationships
  + Frequent read operations
  + High performance requirements
