# Transaction Isolation Anomalies
## What
Transaction isolation anomalies occur when multiple transactions access shared data in a database management system (DBMS) concurrently. Two common types of anomalies are dirty reads and phantom reads. A dirty read occurs when a transaction reads uncommitted data from another transaction, while a phantom read occurs when a transaction sees new data inserted by another transaction that was not present when the first transaction started.

## Why
These anomalies can lead to inconsistencies and incorrect results in database queries. For example, in a financial database, a dirty read could allow a transaction to read an uncommitted withdrawal amount, potentially leading to incorrect account balances. Similarly, a phantom read could cause a transaction to include new data that was not present when the query started, resulting in incorrect aggregation results.

## How
To avoid these anomalies, DBMSs use transaction isolation levels, which define the degree to which a transaction must be isolated from other transactions. The most common isolation levels are:
* Read Uncommitted: allows dirty reads
* Read Committed: prevents dirty reads but allows phantom reads
* Repeatable Read: prevents dirty reads and phantom reads, but may allow non-repeatable reads
* Serializable: prevents all types of isolation anomalies

## One exercise or command
To demonstrate a dirty read, consider the following scenario:
```sql
-- Transaction 1
BEGIN TRANSACTION;
UPDATE accounts SET balance = balance - 100 WHERE account_id = 1;

-- Transaction 2
SELECT balance FROM accounts WHERE account_id = 1;
```
If Transaction 2 reads the updated balance before Transaction 1 commits, it will have performed a dirty read.

## Further reading
* The SQL standard defines four isolation levels: Read Uncommitted, Read Committed, Repeatable Read, and Serializable.
* DBMSs like MySQL, PostgreSQL, and Microsoft SQL Server support various isolation levels.
* Database designers should carefully choose the appropriate isolation level based on the specific requirements of their application.
* Additional anomalies, such as non-repeatable reads, can also occur in certain isolation levels.
