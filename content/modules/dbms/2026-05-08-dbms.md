# TODAY'S FOCUS: Sequential Scan vs Index Scan
## What
The EXPLAIN command in a Database Management System (DBMS) is crucial for understanding how the database executes a query. It provides insight into the query plan, which includes the methods used to access data, such as sequential scans and index scans. A sequential scan involves reading the entire table from start to end, checking each row to see if it meets the query conditions. An index scan, on the other hand, uses an index to find specific rows without having to read the entire table.

## Why
Understanding the difference between sequential scans and index scans is vital for optimizing database queries. Sequential scans can be resource-intensive and slow for large tables, whereas index scans can significantly speed up query execution by directly accessing the required data. Knowing when the database chooses one over the other helps in designing efficient database structures and queries.

## How
The choice between a sequential scan and an index scan depends on various factors, including the size of the table, the selectivity of the query (how many rows are expected to be returned), and the availability and type of indexes on the columns involved in the query. Generally, for small tables or queries that are expected to return a large portion of the table's rows, a sequential scan might be more efficient. For larger tables or queries that are expected to return only a few rows, an index scan, if an appropriate index exists, can be more efficient.

## One exercise or command
To see the difference in action, you can use the EXPLAIN command followed by a SELECT statement. For example, if you have a table named `employees` with an index on the `employee_id` column, you can compare the execution plans of two queries:
```sql
EXPLAIN SELECT * FROM employees WHERE employee_id = 100;
EXPLAIN SELECT * FROM employees WHERE department = 'Sales';
```
The first query, which uses the indexed `employee_id` column, is likely to show an index scan, while the second query, assuming there's no index on the `department` column, might show a sequential scan.

* Understanding [index types](https://www.postgresql.org/docs/current/indexes-types.html) can help in deciding which indexes to create to support your queries efficiently.
* Database tuning guides often discuss the trade-offs between sequential scans and index scans in the context of query optimization and database performance.
