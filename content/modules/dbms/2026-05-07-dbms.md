# EXPLAIN Basics: Sequential Scan vs Index Scan
## What
The EXPLAIN command in DBMS is used to analyze and understand the execution plan of a query. It provides detailed information about the query execution, including the type of scan used, the number of rows scanned, and the cost of the query. There are two primary types of scans: sequential scan and index scan. A sequential scan involves reading all rows in a table, whereas an index scan uses an index to quickly locate specific rows.

## Why
Understanding the difference between sequential scan and index scan is crucial for optimizing query performance. Sequential scans can be slow and resource-intensive, especially for large tables. On the other hand, index scans can significantly improve query performance by reducing the number of rows that need to be scanned. By using the EXPLAIN command, developers can identify whether a query is using a sequential scan or an index scan and take necessary steps to optimize the query.

## How
To use the EXPLAIN command, simply prefix the query with the keyword EXPLAIN. The command will return a detailed execution plan, including the type of scan used, the number of rows scanned, and the cost of the query. For example, if a query is using a sequential scan, the EXPLAIN command may return a plan that looks like this: Seq Scan on table_name. If a query is using an index scan, the plan may look like this: Index Scan using index_name on table_name.

## One exercise or command
Try running the following command to see the execution plan for a query: EXPLAIN SELECT * FROM table_name WHERE column_name = 'value';
