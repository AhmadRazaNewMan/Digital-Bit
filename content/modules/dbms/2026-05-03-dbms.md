# EXPLAIN basics — sequential scan vs index scan
## What
EXPLAIN is a command in Database Management Systems (DBMS) used to analyze and optimize query performance. It provides detailed information about the query execution plan, including the type of scan used to retrieve data.

## Why
Understanding the difference between sequential scan and index scan is crucial for optimizing query performance. A sequential scan involves reading the entire table from disk, which can be time-consuming for large tables. On the other hand, an index scan uses an index to quickly locate specific data, reducing the amount of data that needs to be read.

## How
When a query is executed, the DBMS decides whether to use a sequential scan or an index scan based on the query conditions and the availability of indexes. If an index is available and the query conditions match the index columns, the DBMS will likely use an index scan. Otherwise, it will use a sequential scan.

## One exercise or command
To demonstrate the difference between sequential scan and index scan, consider the following example:
```sql
CREATE TABLE customers (
  id SERIAL PRIMARY KEY,
  name VARCHAR(50),
  email VARCHAR(100)
);

CREATE INDEX idx_email ON customers (email);

EXPLAIN SELECT * FROM customers WHERE email = 'john@example.com';
```
This command will show the query execution plan, indicating whether a sequential scan or an index scan is used.
