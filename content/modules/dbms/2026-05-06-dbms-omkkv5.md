# Transaction Isolation Anomalies
## What
Transaction isolation anomalies refer to the problems that occur when multiple transactions access shared data in a database management system (DBMS) concurrently. Two common types of isolation anomalies are dirty read and phantom read. A dirty read occurs when a transaction reads data that has been modified by another transaction that has not yet committed. A phantom read occurs when a transaction reads data that was inserted or deleted by another transaction that has not yet committed.

## Why
Understanding transaction isolation anomalies is crucial in DBMS because they can lead to inconsistent and unreliable data. Dirty reads can cause transactions to make decisions based on incorrect data, while phantom reads can cause transactions to miss or duplicate data. These anomalies can have significant consequences in applications where data accuracy and consistency are critical, such as financial transactions or medical records.

## How
To prevent transaction isolation anomalies, DBMS uses various isolation levels, such as READ UNCOMMITTED, READ COMMITTED, REPEATABLE READ, and SERIALIZABLE. Each isolation level provides a different level of protection against dirty reads and phantom reads. For example, the REPEATABLE READ isolation level prevents dirty reads but may still allow phantom reads. The SERIALIZABLE isolation level prevents both dirty reads and phantom reads but can have significant performance implications.

## One exercise or command
To demonstrate a dirty read, consider the following example: 
* Start two transactions, T1 and T2.
* In T1, update a row in a table and do not commit.
* In T2, read the updated row.
* If T2 can read the updated row, it is a dirty read.
