# Rate Limiting Per User vs Per IP
## What
Rate limiting is a technique used to control the number of requests a user or IP address can send to a server within a certain time frame. This can help prevent abuse, denial-of-service (DoS) attacks, and improve overall system performance. There are two common approaches to rate limiting: per user and per IP.

## Why
Per user rate limiting is more secure, as it prevents a single user from overwhelming the system, even if they are using multiple IP addresses. On the other hand, per IP rate limiting is simpler to implement, as it only requires tracking the IP address of incoming requests. However, this approach can be bypassed by users who have access to multiple IP addresses.

## How
To implement rate limiting per user, you need to track user IDs or authentication tokens and store the request counts in a database or cache. For per IP rate limiting, you can use IP address as the key to store request counts. You can use algorithms such as token bucket or leaky bucket to implement rate limiting.

## One exercise or command
Try implementing a simple rate limiter using the token bucket algorithm: 
* Set a rate limit of 5 requests per minute per user
* Use a dictionary to store the request counts for each user
* For each incoming request, check if the user has exceeded the rate limit
* If exceeded, return an error message; otherwise, increment the request count

## Further reading
* Advantages and disadvantages of per user vs per IP rate limiting:
  + Per user: more secure, but requires user authentication
  + Per IP: simpler to implement, but can be bypassed
* Token bucket algorithm:
  + Each user has a token bucket that is filled at a constant rate
  + Each request consumes one token from the bucket
  + If the bucket is empty, the request is blocked
* Leaky bucket algorithm:
  + Similar to token bucket, but the bucket leaks at a constant rate
  + Each request adds water to the bucket
  + If the bucket overflows, the request is blocked
