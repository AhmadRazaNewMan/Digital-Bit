# Rate Limiting: Per User vs Per IP
## What
Rate limiting is a technique used to control the number of requests a user or IP address can make to a server within a certain time frame. This can be implemented per user, where the limit is applied based on the user's account or identity, or per IP, where the limit is applied based on the user's IP address.

## Why
Implementing rate limiting per user can help prevent abuse from a single user with multiple IP addresses, while implementing rate limiting per IP can help prevent abuse from multiple users sharing the same IP address. However, per IP rate limiting can also lead to false positives, where multiple legitimate users sharing the same IP address are blocked due to the actions of one user.

## How
To implement rate limiting per user, a backend system can store the user's request history and check it against the rate limit before processing each request. To implement rate limiting per IP, the system can store the IP address and its corresponding request history. The system can then use this information to block or throttle requests that exceed the rate limit.

## One exercise or command
To test rate limiting per user, you can use a tool like `curl` to send multiple requests to your backend system from the same user account, and verify that the system blocks or throttles the requests after the rate limit is exceeded. For example: 
```bash
curl -X GET 'https://example.com/api/endpoint' -H 'Authorization: Bearer user_token'
```
Repeat this command multiple times to test the rate limiting.

## Further reading
* Benefits of rate limiting per user:
  + Prevents abuse from a single user with multiple IP addresses
  + More accurate than per IP rate limiting
* Drawbacks of rate limiting per user:
  + Requires user authentication and tracking
  + Can be more complex to implement
* Benefits of rate limiting per IP:
  + Easier to implement than per user rate limiting
  + Can prevent abuse from multiple users sharing the same IP address
* Drawbacks of rate limiting per IP:
  + Can lead to false positives
  + May not be effective against users with dynamic IP addresses
