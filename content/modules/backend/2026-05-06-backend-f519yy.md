# File Uploads: Streaming vs Buffering Tradeoffs
## What
File uploads are a crucial aspect of many web applications, allowing users to share files with others or store them remotely. When handling file uploads, developers have two primary approaches: streaming and buffering. Streaming involves processing the file in a continuous flow, without loading the entire file into memory. Buffering, on the other hand, involves loading the entire file into memory before processing it.

## Why
The choice between streaming and buffering depends on several factors, including file size, available memory, and performance requirements. Streaming is suitable for large files, as it avoids loading the entire file into memory, reducing the risk of memory overflow. However, streaming can be more complex to implement, especially when dealing with multipart uploads or resumable uploads. Buffering is simpler to implement but can be memory-intensive, making it less suitable for large files.

## How
To implement streaming file uploads, developers can use libraries or frameworks that support streaming, such as Node.js's `stream` module or Python's `streaming-form-data` library. These libraries allow developers to process the file in chunks, reducing memory usage. For buffering, developers can use libraries or frameworks that support buffering, such as Python's `requests` library or Node.js's `busboy` library. These libraries load the entire file into memory before processing it.

## One exercise or command
To demonstrate the difference between streaming and buffering, try uploading a large file (e.g., a 1GB video) using both approaches. Measure the memory usage and upload time for each approach using commands like `top` or `htop` for memory usage and `time` for upload time.
