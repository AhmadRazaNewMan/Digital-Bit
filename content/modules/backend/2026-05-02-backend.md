# Rate Limiting: Per User vs Per IP
## What
Rate limiting is a technique used to control the amount of traffic or requests a user or IP address can send to a server within a certain time frame. It helps prevent abuse, denial-of-service (DoS) attacks, and ensures fair usage of resources. There are two common approaches: rate limiting per user and rate limiting per IP.

## Why
Rate limiting per user is useful when you want to limit the actions of a specific user, regardless of the device or location they are accessing from. On the other hand, rate limiting per IP is useful when you want to limit the actions of a specific IP address, which can be shared by multiple users. The choice between the two approaches depends on the specific use case and requirements of your application.

## How
To implement rate limiting per user, you would typically store the user's ID and request counts in a database or cache. For rate limiting per IP, you would store the IP address and request counts. You can use algorithms such as token bucket or leaky bucket to implement rate limiting. You would also need to consider factors such as time windows, burst tolerance, and fairness when designing your rate limiting system.

## One exercise or command
To test rate limiting per IP, you can use a tool like `curl` to send multiple requests from the same IP address to your server and observe how the rate limiting kicks in. For example: 
`curl -X GET http://example.com/api/endpoint -H "Authorization: Bearer your_token"`
