# REST vs RPC vs GraphQL — when each fits
## What
REST, RPC, and GraphQL are three different approaches to designing web APIs. REST (Representational State of Resource) is an architectural style that focuses on resources and their representations. RPC (Remote Procedure Call) is a protocol that allows a program to call procedures or methods on another program or computer over a network. GraphQL is a query language for APIs that allows clients to specify exactly what data they need.

## Why
Each approach has its own strengths and weaknesses. REST is well-suited for simple, resource-based APIs, while RPC is better for more complex, procedure-based APIs. GraphQL is ideal for APIs that require a high degree of flexibility and customization. Understanding when to use each approach is crucial for building efficient and effective web APIs.

## How
To choose between REST, RPC, and GraphQL, consider the following factors:
* The complexity of the API: REST is suitable for simple APIs, while RPC and GraphQL are better for more complex ones.
* The level of customization required: GraphQL is ideal for APIs that require a high degree of customization.
* The type of data being transferred: REST is well-suited for resource-based data, while RPC is better for procedure-based data.

## One exercise or command
Try designing a simple API using each of the three approaches. For example, create a REST API for a blog, an RPC API for a payment gateway, and a GraphQL API for a social media platform. Compare the strengths and weaknesses of each approach in different scenarios.
