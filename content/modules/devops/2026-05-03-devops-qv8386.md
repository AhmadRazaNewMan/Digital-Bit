# Immutable Artifacts vs Mutable Servers
## What
Immutable artifacts refer to files or packages that cannot be changed once they are created. In contrast, mutable servers are systems that can be modified or updated after deployment. Understanding the differences between these two concepts is crucial in a devops environment.

## Why
Using immutable artifacts provides several benefits, including version control, reproducibility, and security. Since immutable artifacts cannot be changed, any modifications require creating a new version, which helps track changes and ensures that the system remains consistent. On the other hand, mutable servers can lead to configuration drift, where changes are made manually, and the system becomes increasingly difficult to manage.

## How
To implement immutable artifacts, devops teams can use containerization tools like Docker, which packages applications and their dependencies into a single container. This container can then be deployed to any environment without worrying about compatibility issues. Additionally, teams can use tools like HashiCorp's Packer to create identical machine images for deployment.

## One exercise or command
Create a Docker image for a simple web application using the following command:
```bash
docker build -t my-web-app .
```
This command builds a Docker image with the tag "my-web-app" from the instructions in the Dockerfile in the current directory.

## Further reading
* Benefits of immutable infrastructure: 
  * Reduced configuration drift
  * Improved security and compliance
  * Easier rollbacks and version control
* Tools for implementing immutable artifacts: 
  * Docker for containerization
  * Packer for creating machine images
  * Kubernetes for orchestration and deployment
* Best practices for managing mutable servers: 
  * Use automation tools to minimize manual changes
  * Implement version control for server configurations
  * Regularly audit and monitor server configurations for drift
