# Health Checks: Liveness vs Readiness
## What
Health checks are used to determine the status of an application or service, ensuring it is functioning as expected. There are two primary types of health checks: liveness and readiness. Liveness checks verify if an application is running, while readiness checks confirm if the application is ready to receive traffic.

## Why
Distinguishing between liveness and readiness is crucial in a devops environment. Liveness checks help detect if an application has crashed or become unresponsive, allowing for restarts or other corrective actions. Readiness checks, on the other hand, prevent an application from receiving traffic before it is fully initialized and ready to handle requests, reducing errors and improving user experience.

## How
Implementing liveness and readiness checks involves configuring probes that periodically check the application's status. These probes can be based on HTTP requests, TCP connections, or command executions. The specifics of the implementation depend on the application, its dependencies, and the environment in which it runs. Kubernetes, for example, supports both liveness and readiness probes through its pod configuration.

## One exercise or command
To illustrate the difference, consider a simple web server. A liveness check might involve sending an HTTP request to the server's root URL and verifying a successful response. A readiness check, however, might require checking a specific health endpoint that the application exposes, indicating it has completed its startup sequence and is ready for traffic.
