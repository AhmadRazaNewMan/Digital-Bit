# Rolling Deploys and Failure Budgets
## What
Rolling deploys and failure budgets are essential concepts in DevOps that help ensure the reliability and availability of services. Rolling deploys involve gradually replacing instances of an old version of a service with new instances of an updated version, while failure budgets refer to the amount of failure a system can tolerate before it becomes unavailable.

## Why
The purpose of rolling deploys is to minimize downtime and reduce the risk of service interruptions. By gradually replacing old instances with new ones, teams can quickly roll back to a previous version if issues arise. Failure budgets, on the other hand, allow teams to prioritize reliability and availability by setting a threshold for acceptable failures, enabling them to make data-driven decisions about system design and deployment strategies.

## How
To implement rolling deploys and failure budgets, teams can use a combination of automation tools and monitoring systems. For example, they can use containerization platforms like Kubernetes to manage rolling updates, while leveraging monitoring tools like Prometheus and Grafana to track system performance and failure rates. By setting a failure budget, teams can determine the maximum allowable failure rate for a system, and then design deployment strategies that stay within that budget.

## One exercise or command
To get hands-on experience with rolling deploys and failure budgets, try the following command using Kubernetes: `kubectl rolling-update <deployment-name> --image=<new-image-name>`. This command will initiate a rolling update of a deployment, replacing old instances with new ones.

## Senior interview checkpoint

**Prompt:** Draft a rollback plan for failed blue-green deployment with partial data migrations.

**What a senior answer should include**

- Constraints first (traffic, latency, reliability, ownership boundaries).
- Tradeoffs with at least two viable alternatives.
- Failure modes, observability signals, and rollback plan.
- A measurable success criterion after rollout.
