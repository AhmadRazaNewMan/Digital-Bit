# Immutable Artifacts vs Mutable Servers
## What
Immutable artifacts refer to software components that cannot be modified once they are built and deployed. This approach ensures consistency and reliability across different environments. On the other hand, mutable servers are systems that can be modified after deployment, which can lead to configuration drift and inconsistencies.

## Why
The use of immutable artifacts is essential in a devops environment as it provides several benefits, including:
* Improved security and compliance
* Reduced debugging time
* Easier rollbacks and version control
* Increased consistency across environments

## How
To implement immutable artifacts, devops teams can use various strategies, such as:
* Building artifacts from a single source of truth, like a version control system
* Using containerization tools, such as Docker, to create immutable containers
* Employing infrastructure as code (IaC) tools, like Terraform or Ansible, to manage infrastructure configurations

## One exercise or command
Try creating a Docker image with a simple web application, and then attempt to modify the image after it has been built. This will demonstrate the immutability of the artifact:
```bash
docker build -t my-web-app .
docker run -p 8080:80 my-web-app
# Attempt to modify the image
docker exec -it <container_id> /bin/bash
# Modify a file, e.g., echo "Hello, World!" > index.html
# Verify that the changes are not persisted after the container is restarted
docker stop <container_id>
docker start <container_id>
docker exec -it <container_id> /bin/bash
# Check that the changes are lost
```
