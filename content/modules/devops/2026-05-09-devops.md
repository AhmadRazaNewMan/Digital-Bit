# Rolling Deploys and Failure Budgets
## What
Rolling deploys and failure budgets are essential concepts in DevOps that help ensure the reliability and availability of services. Rolling deploys involve gradually replacing old versions of a service with new ones, while failure budgets define the acceptable amount of failures in a system.

## Why
The purpose of rolling deploys is to minimize downtime and reduce the risk of deploying new versions of a service. By gradually rolling out changes, teams can quickly identify and fix issues before they affect a large number of users. Failure budgets, on the other hand, help teams prioritize reliability work and make data-driven decisions about when to roll back or proceed with a deployment.

## How
To implement rolling deploys and failure budgets, teams can use a combination of tools and strategies. This includes:
* using containerization and orchestration tools like Kubernetes
* implementing monitoring and logging systems to track service performance
* setting clear failure budget thresholds and alerting teams when these thresholds are exceeded
* automating rollbacks and other remediation actions

## One exercise or command
To get started with rolling deploys and failure budgets, try running the following command in a Kubernetes cluster: `kubectl rollout status deployment/<deployment-name>`. This command will show the status of a deployment, including the number of replicas and any errors that have occurred.
