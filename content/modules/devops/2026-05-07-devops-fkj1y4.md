# Immutable Artifacts vs Mutable Servers
## What
Immutable artifacts refer to software packages or images that cannot be changed once they are created. This approach is often used in conjunction with mutable servers, which can be modified or updated during their lifetime. The key idea is to separate the immutable, unchanging parts of the system from the mutable, changing parts.

## Why
Using immutable artifacts provides several benefits, including improved security, easier rollbacks, and simplified auditing. Since immutable artifacts cannot be changed, they can be safely stored and reused without worrying about unintended modifications. In contrast, mutable servers can be updated and modified as needed, but their changing nature can introduce complexity and risk.

## How
To implement immutable artifacts and mutable servers, developers can use containerization tools like Docker, which allow them to create and manage immutable images. These images can then be deployed to mutable servers, which can be updated and modified as needed. Another approach is to use infrastructure-as-code tools like Terraform or CloudFormation, which enable developers to define and manage their infrastructure using version-controlled configuration files.

## One exercise or command
Try creating a simple Docker image using the following command: `docker build -t my-image .` This command builds a Docker image with the name "my-image" from the instructions in the current directory's Dockerfile. Once the image is built, it can be used as an immutable artifact and deployed to a mutable server.

## Further reading
* Benefits of immutable infrastructure:
  * Improved security and compliance
  * Easier rollbacks and auditing
  * Simplified debugging and troubleshooting
* Tools for implementing immutable artifacts:
  * Docker and containerization
  * Infrastructure-as-code tools like Terraform or CloudFormation
  * Version control systems like Git
* Best practices for managing mutable servers:
  * Use automation tools to minimize manual changes
  * Implement monitoring and logging to track changes
  * Use version control to track infrastructure configuration changes
