# Health Checks: Liveness vs Readiness
## What
Liveness and readiness are two types of health checks used in DevOps to determine the status of applications and services. Liveness checks verify if an application is running and responding, while readiness checks confirm if an application is ready to receive traffic and process requests.

## Why
Distinguishing between liveness and readiness is crucial for ensuring the reliability and scalability of microservices-based systems. Liveness checks help detect issues that may cause an application to crash or become unresponsive, whereas readiness checks prevent an application from receiving traffic before it is fully initialized and ready to handle requests.

## How
To implement liveness and readiness checks, developers can use various tools and techniques such as:
* HTTP requests to test application responsiveness
* Script-based checks to verify application configurations and dependencies
* Containerization platforms like Kubernetes, which provide built-in support for liveness and readiness probes

## One exercise or command
Run the following command to test the liveness of a web application using `curl`: `curl -f http://example.com/healthz`. If the application is running and responsive, the command will return a successful response; otherwise, it will fail and indicate a liveness issue.
