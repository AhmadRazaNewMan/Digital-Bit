# Rolling Deploys and Failure Budgets
## What
Rolling deploys and failure budgets are essential concepts in DevOps that enable teams to deploy software updates with minimal downtime and manage the risk of failures. Rolling deploys involve gradually replacing old versions of an application with new ones, while failure budgets define the acceptable threshold of errors or failures in a system.

## Why
The primary reason for implementing rolling deploys and failure budgets is to ensure high availability and reliability of systems. By rolling out updates gradually, teams can quickly identify and address issues before they affect a large number of users. Failure budgets help teams to prioritize and manage the trade-off between innovation, quality, and reliability.

## How
To implement rolling deploys and failure budgets, teams need to:
* Monitor system performance and errors in real-time
* Set clear thresholds for acceptable failure rates
* Automate deployment processes to enable gradual rollouts
* Continuously test and validate new versions of the application
* Analyze and learn from failures to improve the overall system

## One exercise or command
Run the following command to simulate a rolling deploy using Kubernetes: `kubectl rollout update deployment <deployment-name> --image <new-image-name>`

## Senior interview checkpoint

**Prompt:** Design CI guardrails to prevent secret leaks and oversized images.

**What a senior answer should include**

- Constraints first (traffic, latency, reliability, ownership boundaries).
- Tradeoffs with at least two viable alternatives.
- Failure modes, observability signals, and rollback plan.
- A measurable success criterion after rollout.
