# Health Checks: Liveness vs Readiness
## What
Health checks are used to determine the status of a container or service in a Kubernetes environment. There are two types of health checks: liveness and readiness probes. Liveness probes check if a container is running and responding correctly, while readiness probes check if a container is ready to receive traffic.

## Why
The distinction between liveness and readiness is important because it allows for more fine-grained control over the deployment and scaling of containers. If a container is not live, it can be restarted. If a container is not ready, it can be removed from the load balancer until it is ready to receive traffic.

## How
Liveness probes are typically used to check for conditions such as:
* A container that is not responding to requests
* A container that is running out of memory or CPU
Readiness probes are typically used to check for conditions such as:
* A container that is still initializing
* A container that is waiting for a dependency to be available

## One exercise or command
To illustrate the difference between liveness and readiness probes, consider a simple web server that takes a few seconds to start up. You can use a command like `kubectl exec` to test the liveness and readiness of the container:
```bash
kubectl exec -it <pod-name> -- curl -s http://localhost:8080/healthz
```
This command checks the health of the container by sending a request to the `/healthz` endpoint. If the container is live and ready, it will return a successful response.
